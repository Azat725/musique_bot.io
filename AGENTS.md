# Инструкция для ИИ-агентов (Codex, Claude Code и любых других)

Этот файл читают Codex (`AGENTS.md`) и Claude Code (через `CLAUDE.md`, который на него ссылается).
Прочитайте его **целиком до первой правки**. Он написан после того, как предыдущие правки сломали приложение:
радио нарисовали одной коробкой, настройки спрятали за двумя уровнями экранов, отступы разъехались, кнопку убрали,
а её обработчик оставили, и плеер перестал запускаться. Всё это пришлось откатывать и переделывать.

Владелец проекта говорит по-русски. **Отвечайте по-русски, коротко и по делу.** Комментарии в коде, имена функций,
сообщения коммитов и тесты пишутся по-английски, как сейчас.

## 0. Главные правила (если прочли только это)

1. **Работайте только в ветке `dev`.** Никогда не пушьте в `main` и не вливайте в него без прямого «да, в main»
   от владельца в этом же разговоре. `main` = сразу публикуется на GitHub Pages и видна всем пользователям.
2. **Не ломайте то, о чём вас не просили.** Не «улучшайте» внешний вид, тексты, названия и структуру по своему вкусу.
   Просят одно: меняйте одно. Хотите предложить другое: напишите, а не делайте.
3. **Ничего не удаляйте наполовину.** Убрали кнопку: уберите и её обработчик, стиль, текст в словаре и тест.
   Добавили функцию: подключите её везде, где она нужна. Ищите все упоминания: `grep -rn "имя" docs server tests`.
4. **Маленькие шаги.** Один коммит: одна законченная вещь. Не смешивайте CI, дизайн, сервер и тексты в одном коммите.
5. **Перед словом «готово» запустите все проверки (раздел 3) и посмотрите результат в браузере** на ширине 375 px
   и 1280 px, в светлой и тёмной теме. Тесты не видят, что кнопка уехала за экран.
6. **Секреты никогда не попадают в репозиторий** (он публичный): токен бота, `server/.env`, `server/cookies.txt`,
   `SUPPORT_URL`, ключи, пароли. Раздел 9.
7. **Не переписывайте большие файлы целиком** и не меняйте окончания строк у всего файла: диффы должны быть
   маленькими и читаемыми. Файлы хранятся с LF.
8. **Честно сообщайте результат.** Тест упал: так и скажите, с выводом. Что-то не проверили: напишите, что не проверили.
   Не маскируйте ошибку, не отключайте тест, чтобы он «позеленел».
9. **Не уверены: спросите владельца.** Лучше один вопрос, чем час переделок.

## 1. Что это за приложение

**Musique**: музыкальный плеер в Telegram (Mini App) плюс бот. Любая песня из YouTube Music и открытых источников
играет на «живой технике»: пластинка, проигрыватель, магнитофон, катушки, портативный CD-плеер, фонограф Эдисона
(50 цилиндров), автомагнитола и домашний радиоприёмник (радио: 49 приёмников, 56 станций, «машина времени»).

- **Клиент**: `docs/`. Чистый JavaScript (ES-модули), без сборки, без фреймворков, без npm-зависимостей в рантайме.
  Публикуется на GitHub Pages из ветки `main`: https://azat725.github.io/musique_bot.io/docs/
- **Сервер**: `server/`. Python 3.12, FastAPI + aiogram в одном процессе, SQLite, yt-dlp, ffmpeg.
  Работает на VPS в Docker за Caddy (`109-66-243-195.sslip.io`, 6 vCPU, 11,7 ГБ ОЗУ).
- **Целевая нагрузка**: сотни, а лучше тысячи слушателей одновременно. Всё, что вы добавляете на сервере, должно
  это выдерживать (раздел 8).
- **Целевые устройства**: телефон в Telegram (iOS WebView и Android), 375 px в ширину, плюс браузер на компьютере.
  iPhone капризнее всего.

Стиль: тёплая бумага, французский флаг (бордо и тёмно-синий) в базовой теме, **только плоские цвета, никаких
градиентов** (раздел 5.1), антикварная техника, аккуратность.

## 3. Как запускать и проверять (Windows, PowerShell или Git Bash)

Виртуальное окружение Python лежит в `.venv` (`.venv\Scripts\python.exe`). Node 24. Перед первой проверкой: `npm ci`.

### 3.1 Статические проверки клиента (быстро, запускайте после каждой правки)
```bash
node scripts/check.mjs
```
Проверяет: синтаксис всех `docs/js/*.js`, что каждый относительный `import` существует и есть в `importmap`
в `docs/index.html`, что нет градиентов в CSS, что все файлы из importmap на месте.

### 3.2 Модульные тесты клиента
```bash
npm test
```

### 3.3 Серверные тесты
Нужны переменные окружения, иначе сервер не стартует: токен-пустышка, пустой env-файл и папка данных.

Git Bash:
```bash
export BOT_TOKEN='123:TEST' ENV_FILE=/dev/null DATA_DIR="$TEMP/musique-test" PYTHONIOENCODING=utf-8
.venv/Scripts/python.exe -m unittest discover -s tests/server -v
```
PowerShell:
```powershell
$env:BOT_TOKEN='123:TEST'; $env:ENV_FILE='none.env'; $env:DATA_DIR="$env:TEMP\musique-test"; $env:PYTHONIOENCODING='utf-8'
.venv\Scripts\python.exe -m unittest discover -s tests/server -v
.venv\Scripts\python.exe -m compileall -q server
```
**Никогда** не запускайте тесты с реальным `BOT_TOKEN` и реальной папкой данных: тесты создают и удаляют файлы.

### 3.4 Браузерные тесты (Playwright)
```bash
npx playwright install chromium          # один раз, если нет браузера
npx playwright test                      # 2 проекта: mobile 375×812 и desktop 1280×800
```
Если скачивать браузер нельзя, возьмите установленный: `PW_CHANNEL=msedge npx playwright test`
(PowerShell: `$env:PW_CHANNEL='msedge'; npx playwright test`; можно `chrome`). Тесты ничего не играют (звук заглушён),
внешние запросы заблокированы, API подменён. **Тесты следуют за интерфейсом:** меняете экран — обновите тест,
но не удаляйте проверку, чтобы «пройти».

### 3.5 Посмотреть своими глазами (обязательно для любых правок интерфейса)
Тесты не заменяют взгляд. Поднимите фальшивый API, который отдаёт треки, станции радио и звук:
```bash
.venv/Scripts/python.exe tests/stub.py docs        # слушает 127.0.0.1:5501
```
Откройте `http://localhost:5501/index.html?api=http://localhost:5501` в браузере (размер окна 375×812, потом 1280×800).
Включите нужный режим через консоль браузера, например радио:
```js
localStorage.setItem('musique.settings', JSON.stringify({lang:'ru', storiesSeen:true, playerMode:'radio-car', deviceHints:{}}))
```
и перезагрузите страницу. Проверьте: экран выглядит как задумано, ничего не вылезает за края, нет ошибок в консоли,
кнопки нажимаются, светлая и тёмная тема (`theme:'light'` / `'dark'` в тех же настройках), другие проигрыватели
не сломались (пройдите по `PLAYER_MODES`).

### 3.6 Нагрузочная проверка сервера (если трогали `server/`)
`tests/load/loadtest3k.py` запускает настоящий API в отдельном процессе, подменяет загрузки и гонит 3000 слушателей,
потом всплеск из 1000 новых треков. Нужен `pip install aiohttp` (только для теста):
```bash
LT_USERS=3000 LT_SECONDS=60 .venv/Scripts/python.exe tests/load/loadtest3k.py
```
Цели: никаких зависших запросов, лишние получают быстрый `503 busy`, `/api/health` отвечает быстро во время всплеска.
На Windows тест упирается в лимит одновременных подключений, это известно и описано в комментарии теста.

## 4. Рабочий процесс (как делать любую задачу)

1. **Пойми задачу.** Перечитай просьбу. Если она большая или неоднозначная, сначала напиши владельцу короткий план
   (что и в каких файлах поменяешь) и дождись ответа.
2. **Посмотри, как это устроено сейчас.** Найди все места, которых коснётся правка (`grep -rn`), прочитай
   соседний код и копируй его стиль: названия, плотность комментариев, способ рисования.
3. **Работай в `dev`**: `git switch dev`. Перед началом `git status`: чужие несохранённые правки не трогай и не
   откатывай (`git checkout -- файл`, `git reset --hard`, `git stash drop`, `git clean` без прямой просьбы запрещены).
4. **Меняй минимально.** Для небольших правок используйте точечную замену, а не переписывание файла.
   Для многострочных правок на Windows удобнее короткий Python-скрипт с проверкой `assert старый_текст in файл`:
   если подстрока не найдена, скрипт падает, и вы не получите молчаливо испорченный файл.
5. **После каждого логического шага** запускайте `node scripts/check.mjs`.
6. **Подними версию модулей** после любой правки в `docs/` (раздел 5.2).
7. **Прогони все проверки** (3.1–3.4, плюс 3.6 для сервера) и **посмотри в браузере** (3.5).
8. **Закоммить** (раздел 4.1). Один коммит = одна законченная вещь.
9. **Отчитайся владельцу** по-русски: что сделано (по пунктам, простыми словами), что проверено и чем, что не
   проверено, что нужно сделать владельцу (например, обновить VPS), и спроси: «Влить в main и выпустить?».
   **Дальше не идти без ответа «да».**

### 4.1 Коммиты
- Английское сообщение: короткая первая строка в повелительном наклонении, при необходимости пустая строка и
  список «что и зачем». Пример: `Radio: tune stations from the receiver's preset keys`.
- Не коммитьте: `node_modules`, `dist`, `test-results`, `playwright-report`, `.venv`, базы `*.db`, `server/cache`,
  `server/.env*`, `cookies.txt`, логи туннеля, любые файлы со ссылками и ключами.
- Не используйте `--no-verify`, `--amend` для уже запушенных коммитов, `push --force`, `revert` чужих коммитов
  «для порядка». Ошиблись: новый коммит с исправлением.
- Предупреждения `LF will be replaced by CRLF` на Windows нормальны. Но если `git diff --stat` показывает тысячи
  изменённых строк в файле, где вы поправили три, вы случайно сменили окончания строк. Откатите файл и повторите правку.

### 4.2 Выпуск в `main` (делает владелец или вы по его прямому слову)
Только после явного «да, в main» в этом разговоре:
```bash
git push -q origin dev:main && git branch -f main dev && git push -q origin dev
```
(`release.ps1` интерактивный, из агента его не запускайте.) GitHub Pages обновится за 1–2 минуты.
**Если менялся `server/`, `Caddyfile`, `docker-compose.yml` или `requirements.txt`**, сообщите владельцу, что на VPS
нужно выполнить:
```bash
cd ~/musique && git pull && docker compose --env-file server/.env up -d --build
```
Если менялся `Caddyfile`, добавьте проверку: `docker compose exec caddy caddy validate --config /etc/caddy/Caddyfile`.
Деплой на VPS агент не делает и по SSH на сервер не заходит.

## 5. Правила клиента (`docs/`)

### 5.1 Стиль и CSS
- **Только плоские цвета.** Запрещены `linear-gradient`, `radial-gradient`, `conic-gradient` и их `repeating-*`.
  `scripts/check.mjs` это ловит. Нужна полоска или рябь: используйте `border` (в том числе `dashed`/`dotted`),
  `box-shadow` с несколькими плоскими слоями, SVG-фигуры.
- **Цвета берите из токенов** (`var(--bg)`, `--surface`, `--text`, `--text-2`, `--accent`, `--accent-text`, `--line`...).
  Шестнадцатеричные цвета внутри картинок техники (SVG в `devices/*.js`, `receivers.js`) допустимы: это нарисованные
  предметы. В обычных экранах и листах цвет задаётся токеном, чтобы работали 13 тем × светлая и тёмная.
- **Шкала отступов в `tokens.css`, пользуйтесь только ею:**
  `--gutter` (16 px: отступ контента от края экрана, одинаков на всех экранах), `--s1…--s6` (4, 8, 12, 16, 24, 32),
  `--gap` (12: между соседними элементами), `--section-gap` (28: между блоками страницы), `--card-y`/`--card-x`
  (14/16: внутри карточки), `--col` (720: ширина колонки на компьютере), радиусы `--r-sm`, `--r-md`, `--r-lg`.
  **Не вписывайте «ещё один» `padding: 18px`.** Если нужного значения нет, возьмите ближайшее из шкалы.
  Проверка: левый край контента на каждом экране ровно на 16 px, блоки одинаково разнесены.
- Выбранный элемент не должен менять размер (не делайте `border: 2px` вместо `1px`; используйте `box-shadow: inset`).
- Касаемая область не меньше 44×44 px; видимый фокус (`:focus-visible`) не убирайте.
- Всё должно работать без горизонтальной прокрутки на 375 px. Проверка: `document.documentElement.scrollWidth <= innerWidth`.
- Уважайте `prefers-reduced-motion` для постоянных анимаций.
- Комментарий `/* ... */` в CSS **всегда закрывайте**. Один незакрытый комментарий однажды «съел» полстраницы токенов
  и сломал высоту навигации и плеера. После правки CSS смотрите экран, а не только `check.mjs`.

### 5.2 Модули и версии (iOS кэширует модули по адресу!)
- Код разделён на ES-модули. В `docs/index.html` есть `<script type="importmap">` со всеми модулями и `?v=NN`.
  **Новый файл в `docs/js/` без записи в importmap не загрузится.**
- После **любой** правки в `docs/` (JS, CSS, HTML) поднимите версию: посмотрите текущую в `docs/index.html`
  (`?v=NN`) и выполните `node scripts/version.mjs <NN+1>`. Скрипт перепишет importmap и все `?v=`.
  Без этого у пользователей останется старая версия из кэша WebView.
- Импорты внутри модулей пишутся без `?v=` (`import { t } from './i18n.js'`): подставляет importmap.
- Никаких новых npm-пакетов, CDN-скриптов и внешних библиотек в клиенте. Единственные внешние запросы: сервер
  Musique и (если включён «шрифт темы») Google Fonts. Telegram-скрипт лежит в `docs/vendor/`.

### 5.3 Тексты и переводы (i18n)
- **Каждая строка интерфейса** идёт через `t('ключ')`, **в обоих языках** (`ru` и `en`). Нельзя оставлять ключ
  в одном языке: пользователь увидит `radio_foo` вместо текста.
- Словари: `docs/js/ux-i18n.js` (новые тексты; **они подставляются последними и перекрывают одноимённые ключи**
  из `docs/js/i18n.js`). Новые тексты добавляйте в `ux-i18n.js`, старые не дублируйте.
- Для разных проигрывателей работают варианты ключей: `ключ_tape` (магнитофон и катушки), `ключ_reel`, `ключ_cd`,
  `ключ_radio`; `setLook(playerMode)` выбирает их сам. Это нужно, чтобы у катушек не было «пластинки».
- Подстановки: `t('radio_era_of', { d: 1960 })` заменяет `{d}`.
- Перед коммитом проверьте, что для каждого нового `t('...')` есть ключ в `ru` и в `en`. Быстрая проверка:
  найдите все `t('имя')` в изменённых файлах (`grep -rhoE "t\('[a-z_0-9-]+'" docs/js`) и убедитесь, что каждое
  имя есть в обоих словарях. Динамические ключи (`'theme_' + id`, `'country_' + code`) проверяйте глазами по списку.
- Тексты для людей: простые, на «вы», без жаргона. Подсказка у каждой настройки: что она делает.
- Названия приёмников, машин, станций и тем: настоящие, но рисунки стилизованные, **не копии**; логотипов
  производителей не рисуйте.

### 5.4 Настройки и данные пользователя (`store.js`)
- Все настройки живут в объекте `settings` (`store.js`), сохраняются в `localStorage`, Telegram CloudStorage и
  синхронизируются между устройствами аккаунта. Ключи, которые не должны ехать между устройствами (скачанное,
  подсказки), перечислены в `DEVICE_ONLY`.
- **Нельзя переименовывать или удалять ключ настроек без миграции** в `migrate()` (она запускается при каждой загрузке и
  при получении настроек с другого устройства). Пример миграции радио уже есть. Иначе у людей сбросится оформление.
- Размер настроек, уходящих на сервер, ограничен 20 КБ. Не кладите в настройки списки треков и картинки.
- Новая настройка: значение по умолчанию в `settings`, переключатель в `views/settings.js`, подпись и подсказка
  в обоих словарях, при необходимости ключ в `LOOK_KEYS` (`customization.js`), если она входит в «оформление».

### 5.5 Экраны и настройки
- Настройки: **одна страница**, всё применяется **сразу** (без кнопки «Применить»). Группы с заголовком, у каждой
  строки подсказка. Проигрыватели выбираются карточками, цвета рядом, темы сеткой. Не возвращайте двухуровневые
  страницы и черновики с «Применить». Не прячьте существующие настройки.
- Каждый экран: заголовок `view__title`, блоки `section` / `group`, пустые состояния через `.empty`, ошибка с кнопкой
  «Повторить». Скелет экрана смотрите в `views/home.js` и `views/settings.js`.
- Подписки на глобальные события (`document`, `window`, `onSettings`) оформляйте через `viewScope(root)`
  (`lifecycle.js`), иначе они текут при каждом заходе на экран.
- Листы и диалоги (`sheet()`, `confirmSheet()`, `promptName()`) уже умеют фокус и закрытие по Escape: используйте их,
  не пишите свои. Подтверждение нужно перед необратимым (удалить, очистить).

### 5.6 Проигрыватели (`devices/`, `vinyl.js`)
Проигрыватель = модуль в `docs/js/devices/` с общим интерфейсом (см. начало `devices/common.js` и любой готовый
модуль, например `cd.js`): `id`, `family`, `deck()` (разметка), `media(track)`, `show()`, `sync()`, `onKey()`
(необязательный: свои кнопки), `sounds`, `leave`/`arrive`. `vinyl.js` только дирижирует, ветвления по режимам там
писать не нужно.

Чтобы **добавить проигрыватель**: модуль в `devices/`, запись в `devices/index.js` (`PLAYER_MODES`, `DEVICES`), иконка
`pm_<id>` в `ui.js`, тексты `player_<id>` и `pm_desc_<id>` в обоих словарях, стили в `devices.css`, строка в карточках
выбора (`PLAYERS` в `stories.js`), тесты (`ux.spec.cjs` проходит по всем режимам), цвета в `themes.js` и
`settings.js`, если они настраиваются. Проверьте плеер в режиме «Только техника» и миникарточку.

**Режим «Только техника»**: под устройством нет названия, полосы и кнопок. Выход: переключатель в Настройках и
пункт «Показать кнопки плеера» в меню «⋯» плеера. **Кнопки «Показать управление» на сцене нет и не должно быть**
(подсказка устройства её раньше перекрывала, а при удалении остался обработчик, и плеер не запускался).

### 5.7 Радио (`radio.js`, `devices/radio.js`, `devices/receivers.js`)
- **Приёмник задаёт эпоху и страну** (Fiat 500 1965 играет Италию 1960-х). Кнопки приёмника: родная страна, потом
  остальные страны того же десятилетия, последняя «Ваша волна». **Не возвращайте независимый выбор модели, страны и
  десятилетия:** он давал «Citroën DS · США».
- Настройки радио: `radioCar`, `radioHome` (id приёмника), `radioStation`, `radioEra` (звук AM), `radioRain`, `radioRoad`.
- **Новый приёмник**: объект в `CARS` или `HOMES` в `receivers.js` (`id`, `name`, `year`, `country`, `unit`, `band`
  `am|fm`, `screen` = место шкалы/дисплея в координатах рисунка, `art()` = плоские SVG-фигуры). Он должен быть узнаваем
  по характерной примете. Обязательно: кнопки `data-key` `toggle`, `tune`, `preset`. Проверьте рисунок в браузере в
  обеих темах. Любой приёмник до 1970 года звучит как средние волны (`band: 'am'` включает эффект `am`).
- **Новая страна или десятилетие**: список песен в `server/radio_seeds.json` (`страна → десятилетие → [[исполнитель,
  название, год]]`, не меньше 10 песен на станцию, год в пределах десятилетия, **только широко известные записи**),
  коды в `COUNTRIES`/`AM`/`FM` в `radio.js`, тексты `country_*` и `station_*`. Тест `test_radio.py` проверяет полноту.
- **Дождь и дорога** (только автомобиль) считаются в `sfx.js` (`startCarAmbience`) и CSS (`.rx__glass`, `.rx__rain`,
  `.rx__lines`). Звуки синтезируются. Заменять их записями можно только с лицензией CC0 и записью в
  `docs/assets/sfx/CREDITS.md`.

### 5.10 Мини-игра «За рулём» (`docs/js/drive/`)
- Работает **только на клиенте, не делает ни одного запроса** (тест `ux.spec.cjs` это проверяет). Единственное исключение:
  удержание радио 2,5 с вызывает `tuneBy(1)` из `radio.js`, то есть обычную смену станции, как кнопка в плеере.
- Вход: кнопка с рулём (`data-drive`) в верхней панели плеера, видна только в режиме `radio-car`; перед игрой всегда
  предупреждение (`sheet()`). Игра грузится `import('./drive/game.js')` по требованию; `body.drive-open` говорит `app.js`
  (Escape, кнопка «Назад»), что «назад» сначала закрывает игру.
- Чистая логика без импортов и без DOM (её тестирует `tests/unit/drive.test.cjs` через `data:`-импорт): `world.js` (город
  8 × 8 кварталов, 960 м, `onRoad`), `physics.js` (машина, коробка, бордюр), `traffic.js` (другие машины по петлям,
  люди на тротуарах), `styles.js` (страна и эпоха → дома, кузова, сторона дороги, двигатель по id машины). Не добавляйте в
  них `import`: тест перестанет их загружать.
- `render.js`: canvas, своя перспектива, **только плоские цвета** (никаких `createLinearGradient`); `dash.js`: панель
  берётся из `art()` выбранного приёмника (руль вынут из рисунка, стрелки и полосы оживают), поэтому у **новой машины в
  `receivers.js` панель в игре появляется сама**. Нужны движок и размеры: строка в `SPECS` (`styles.js`), иначе берётся
  «Гольф». Приборы «непривычной» формы описываются в `ODD`/`SWAP` (`dash.js`).
- Нельзя: съехать с дороги (всё вне `onRoad` непроходимо), тянуть данные из сети, играть звук при выключенных «Звуках»
  (`startDriveAudio` в `sfx.js` берёт `hold()/release()`).

### 5.8 Темы
13 тем × светлая/тёмная (`classic` + 12 цветных). Чтобы **добавить или изменить тему**, правятся согласованно ТРИ места
(генератор палитр в репозиторий не входит, значит, руками и внимательно):
1. `docs/css/tokens.css`: два блока `:root[data-theme="id"][data-mode="light"|"dark"]` со всеми токенами;
2. `docs/js/themes.js`: запись в `THEMES` (`bg` и `swatch` для обоих режимов);
3. `docs/index.html`: таблица фонов в раннем скрипте (`ussr: ['#F1E6CC', '#2A0F10']` и т. п.).
Плюс: тексты `theme_<id>` и `theme_desc_<id>`, шрифт в `fonts.js` и в `app.css` (`data-theme-font`).
**Контраст текста и акцента не ниже 4,5 : 1 в каждом режиме.** Проверьте глазами оба режима.

### 5.9 Звуки
Только синтез Web Audio или записи с лицензией **CC0**, с записью об авторе и ссылке в `CREDITS.md`. Звуки не должны
играть при выключенном переключателе «Звуки». Аудиоконтекст усыпляется, когда ничего не играет (иначе iOS «глохнет»):
пользуйтесь `hold()`/`release()` в `sfx.js`. Не подключайте основной `<audio>` к Web Audio без нужды: пока эквалайзер
выключен, музыка идёт напрямую (так надёжнее на iPhone, см. комментарий в `graph.js`).

## 6. Правила сервера (`server/`)

Прочитайте `music.py`, `db.py` и `api.py` целиком, прежде чем править: в них уже решены задачи нагрузки.

- **Ничего блокирующего в асинхронном коде.** Файлы, ffmpeg, yt-dlp, тяжёлый JSON: в потоки или процессы.
  ffmpeg: `await _ff(fn, ...)` (свой пул потоков), загрузки yt-dlp: `await _offload(fn, ...)` (пул процессов), прочее:
  `asyncio.to_thread`. **Не вызывайте `glob`/`os.listdir` кэша на каждый запрос**: используйте индекс `_cached_file()`.
- **База (`db.py`)**: одно соединение в своём потоке. Не открывайте другие соединения для записи. Пишите через
  `_write(функция, ...)`: функция (синхронная, внутри `_conn.execute`) выполняется в одной транзакции с точкой
  отката, а фиксация происходит через 0,25 с вместе с другими. Для чтения: `_run(_q|_one, ...)`. Нужна запись, которую
  нельзя терять до ответа (сессия, слияние аккаунтов): `now=True`. Новая таблица: добавьте в `SCHEMA`, индекс под
  запросы, миграцию для старых баз (`ALTER TABLE` в `_init`).
- **Очередь загрузок (`Gate`, `ensure_file`)**: уже ограничивает загрузки (6), ожидающих (160) и время ожидания (45 с),
  объединяет загрузки одного трека, исключает ушедших слушателей. **Не обходите её** прямыми вызовами yt-dlp. Новая
  тяжёлая операция: приоритет `PLAY`/`NEXT`/`BG` и `drop`, как в `prefetch`.
- **Новый маршрут**: проверка пользователя `user=User`, ограничение частоты через `_limit(user, 'вид')` (добавьте вид в
  `LIMITS`), валидация входных данных (pydantic с `Field(max_length=…)`), ограничение размеров, понятный код ошибки
  (`400/403/404/429/503`), тест. Входящие метаданные трека от клиента **не доверенные**: не берите из них названия для
  поиска замены аудио.
- **Кэши в памяти ограничены** (`_trim`, лимиты размера). Новый словарь без предела запрещён. Одинаковые одновременные
  запросы к внешним сервисам объединяйте через `_once(ключ, функция)`. Неудачи не кэшируйте как результат.
- **Раздача музыки**: `/api/stream` отвечает `X-Accel-Redirect`, файл отдаёт Caddy (`STREAM_ACCEL=1`). Не возвращайтесь к
  чтению файлов в Python. Заголовки `Cache-Control` и `Range` сохраните.
- **Эффекты ffmpeg**: имя эффекта проверяется `FX_RE`; новый эффект добавляется в `FX_RE`, `_fx_filter`, клиентский
  `_fxFor` и получает тест на тестовом сигнале (как `test_am_is_mono_and_narrow`).
- **Радио**: сервер ищет песни станций сам, один раз, и хранит найденное в `DATA_DIR/radio_resolved.json`. Во время
  работы запросов слушателей поиска нет. Не добавляйте поиск «на лету».
- **Секреты и логи**: не печатайте токены, куки, `initData`, адреса пользователей. Исключения логируйте коротко
  (`str(e)[:200]`), без полных трассировок на каждый запрос.
- **Зависимости**: `server/requirements.txt` с верхними границами. Новую зависимость добавляйте только при
  необходимости и сообщайте владельцу (образ Docker пересобирается на VPS).
- Изменения в `Caddyfile`, `docker-compose.yml` и `Dockerfile` делаются только по просьбе владельца и всегда
  сопровождаются проверкой `caddy validate`/`docker build` и записью в `DEPLOY.md`.

## 10. Если что-то пошло не так

- Сломали и не знаете как: **остановитесь**, опишите владельцу, что именно упало (вывод команды целиком), и что вы
  пробовали. Не лечите поломку массовыми правками.

- Тесты падают из-за окружения (нет браузера, нет сети, VPN): так и скажите. Не отключайте тесты.
- Задача требует решения, которое владелец не одобрял (платная услуга, смена хостинга, новая зависимость, удаление
  функции): сначала спросите.
